# Практическая работа №2. File Integrity Monitoring (FIM) в Wazuh

## Описание проекта

В данной практической работе я изучил и настроил механизм File Integrity Monitoring (FIM) в Wazuh.

FIM используется для отслеживания изменений файлов и директорий на конечных устройствах. Он позволяет обнаруживать создание, изменение и удаление файлов, а также фиксировать изменения их контрольных сумм.

В качестве тестовой среды использовались Wazuh Server и Windows Endpoint с установленным Wazuh Agent.

## Цели работы

- Изучить принцип работы File Integrity Monitoring.
- Разобраться с настройками FIM в конфигурации Wazuh Agent.
- Настроить мониторинг отдельной директории Windows.
- Проверить обнаружение создания, изменения и удаления файлов.
- Изучить события, которые генерирует Wazuh при изменении файлов.
- Понять, как FIM применяется для обнаружения подозрительной активности.

## Окружение

- **SIEM:** Wazuh
- **Endpoint:** Windows
- **Agent:** `egorgogo`
- **Тестовая директория:** `C:\FIM-Lab`
- **Конфигурационный файл:** `ossec.conf`

## 1. Проверка существующей конфигурации FIM

Перед началом эксперимента я проверил конфигурацию Wazuh Agent.

В стандартной конфигурации уже был включён механизм Syscheck, который отвечает за File Integrity Monitoring.

Основные параметры:

```xml
<syscheck>
    <disabled>no</disabled>
    <frequency>43200</frequency>
</syscheck>
```

Параметр `disabled=no` означает, что FIM включён.

Параметр `frequency=43200` задаёт периодическую проверку каждые 43 200 секунд, то есть раз в 12 часов.

Также в конфигурации уже присутствовали системные директории Windows, которые отслеживались Wazuh.

## 2. Создание тестовой директории

Для проведения эксперимента была создана отдельная директория:

```powershell
New-Item -ItemType Directory -Path "C:\FIM-Lab" -Force
```

Я решил использовать отдельную тестовую папку, чтобы не изменять системные файлы Windows и не создавать лишнюю нагрузку на систему.

## 3. Настройка мониторинга директории

В конфигурационный файл агента `ossec.conf` был добавлен следующий параметр внутри существующего блока `<syscheck>`:

```xml
<directories check_all="yes" realtime="yes">C:\FIM-Lab</directories>
```

Параметры настройки:

- `check_all="yes"` включает проверку всех поддерживаемых атрибутов файла, включая контрольные суммы.
- `realtime="yes"` включает отслеживание изменений в реальном времени.

После изменения конфигурации служба Wazuh Agent была перезапущена:

```powershell
Restart-Service WazuhSvc
```

Состояние службы было проверено с помощью:

```powershell
Get-Service WazuhSvc
```

Служба успешно запустилась и имела статус `Running`.

## 4. Проведение эксперимента

После настройки мониторинга были выполнены три тестовых действия в директории `C:\FIM-Lab`:

1. Создание нового файла.
2. Изменение содержимого существующего файла.
3. Удаление файла.

После выполнения каждого действия я проверял события, поступившие в Wazuh Dashboard.

## 5. Результаты мониторинга

В Wazuh Dashboard были обнаружены события, соответствующие выполненным действиям.

Основные типы обнаруженных событий:

- `File added to the system` - обнаружено создание нового файла.
- `Integrity checksum changed` - обнаружено изменение контрольной суммы файла.
- `File deleted` - обнаружено удаление файла.

Все события поступили от Windows-агента `egorgogo`.

Это подтвердило, что настроенный FIM отслеживает изменения в выбранной директории и передаёт информацию в Wazuh.

## 6. Значение FIM для SOC

File Integrity Monitoring является полезным инструментом для обнаружения изменений в файловой системе.

Например, с его помощью можно отслеживать:

- Изменения системных файлов.
- Появление новых файлов в важных директориях.
- Изменения конфигурационных файлов.
- Изменения в папках автозагрузки.
- Удаление важных файлов.

При этом само по себе изменение файла не означает наличие атаки. Для расследования необходимо учитывать контекст события, время изменения, путь к файлу и другие доступные данные.
